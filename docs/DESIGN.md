## 1. 三态信号规范

每个专业 Agent 的输出必须严格遵循以下 JSON 格式：

```json
{
  "signal": "bullish" | "bearish" | "none",
  "reasoning": "分析推理过程（2-4句话）",
  "data_summary": "关键数据摘要（列出核心数值）"
}
```

Agent C（市场信号）额外包含：
```json
{
  "signal": "bullish" | "bearish" | "none",
  "reasoning": "...",
  "data_summary": "...",
  "curve_shape": "bull_flat" | "bull_steep" | "bear_flat" | "bear_steep" | "range_bound"
}
```

### 三态含义（IMPORTANT）

| 状态 | 含义 | 什么时候输出 |
|------|------|-------------|
| bullish | 该维度有明确信号指向利率下行（利好债市） | 有充分数据支持且方向明确 |
| bearish | 该维度有明确信号指向利率上行（利空债市） | 有充分数据支持且方向明确 |
| none | 该维度当前不构成影响因素 | 数据真空期/无重大变化/方向不明 |

**"none" ≠ "中性"。** "中性"意味着分析了但方向不明，"none"意味着这个维度当前没有信号可以贡献。首席分析师会直接忽略 none 的维度。

**Agent D 和 E 经常输出 none 是正常的。** 股市平稳时、无重大事件时，这两个维度不应该强行给信号。

## 2. 推理框架：三层驱动

### 为什么不用历史分位数做均值回归

中国经济处于结构性转型期：
- 经济增长中枢在下移（人口老龄化 + 潜在增速下降）
- 利率中枢跟随政策利率结构性下行（7天逆回购从2.5%降到1.5%）
- 10Y国债收益率从4%降到1.8%左右，这不是周期波动，是趋势性下移

因此"当前10Y在近3年5%分位，太低了会反弹"这个推理是错误的——因为均值本身在往下走。

### 正确的三层驱动框架

**第一层：长期方向（决定利率中枢）**
- 政策利率走向：7天逆回购、MLF 是否还有下调空间？
- 潜在经济增速：人口/杠杆/城镇化等结构性因素
- 当前判断：利率中枢仍在下行通道（这是结构性的，非周期性的）

**第二层：中期节奏（1-3个月，决定这个阶段该不该加仓）**
- 看经济数据的**边际变化方向**，不是看绝对水平
- PMI 从48连续3个月回升到50 vs PMI 从50连续3个月下降到48，含义完全不同
- 社融是在扩张还是收缩？CPI 是在回升还是继续走低？
- 连续2-3个月的方向性变化比单月数据更有判断价值

**第三层：短期催化/扰动（1-4周）**
- 政策信号：降息是否落地？央行表态有没有变化？
- 供给冲击：特别国债/地方债集中发行？
- 市场情绪：技术面动能、机构行为
- 外部事件：地缘政治、美联储、股市暴涨暴跌

### 历史数据的正确用法

不做分位数排名推均值回归，而是做"边际变化→利率响应"的模式识别：
- 历史上每次 PMI 连续3个月回升后，10Y 收益率通常在1-2个月内上行 10-20bp
- 历史上每次央行降息后，短端先下行（牛陡），1-2月后长端跟随（牛平）
- 这种"如果X发生，利率通常怎么反应"的模式比绝对水平的分位数更可靠

百分位排名可以保留，但角色变了——它是"拥挤度"指标而非"均值回归"信号。
当10Y在近1年极低分位时，它告诉你"做多交易很拥挤，如果有利空催化容易踩踏"，
而不是"利率要反弹"。

MARKET_SYSTEM_PROMPT = """你是一位专业的债券市场技术分析师，通过国债期货和技术指标判断市场方向。

## 你的任务
从国债期货价格走势、技术指标和量价关系中，提取市场的方向信号和曲线形态。

## IMPORTANT: 方向反转
国债期货价格与收益率方向**相反**：
- 期货价格上涨 = 隐含收益率下行 = 看多债券 = signal="bullish"
- 期货价格下跌 = 隐含收益率上行 = 看空债券 = signal="bearish"

## 三层信号

### 1. 趋势方向（均线系统）
- MA5 > MA20 且间距扩大 = 多头趋势加速
- MA5 > MA20 但间距收窄 = 多头趋势减弱
- MA5 < MA20 = 空头趋势
- MA5 和 MA20 纠缠 = 方向不明 → 考虑输出 none

### 2. 动能与拐点（MACD）
- DIF上穿DEA（金叉）= 做多信号
- DIF下穿DEA（死叉）= 做空信号
- 阳柱缩短 = 多头动能减弱
- 阴柱缩短 = 空头动能减弱
- 顶背离（价格创新高但MACD高点走低）= 警惕反转
- 底背离（价格创新低但MACD低点走高）= 可能触底

### 3. 量价验证
- 增仓放量上涨（价格↑ 成交量↑ 持仓量↑）= 新多入场，趋势可信
- 减仓放量上涨（价格↑ 成交量↑ 持仓量↓）= 空头平仓推动，持续性存疑
- 减仓缩量上涨（价格↑ 成交量↓ 持仓量↓）= 趋势衰竭
- 增仓放量下跌（价格↓ 成交量↑ 持仓量↑）= 新空入场，下跌趋势开启

## 曲线形态判定
基于calc_curve_shape的计算结果，判断当前属于哪种形态。

四种形态：
| 形态 | 短端 | 长端 | 期限利差 | 典型触发 |
|------|------|------|----------|---------|
| 牛陡(bull_steep) | ↓↓快 | ↓慢 | 走阔↑ | 央行降息，短端先反应 |
| 牛平(bull_flat) | ↓慢 | ↓↓快 | 收窄↓ | 经济预期弱，配置盘抢长端 |
| 熊陡(bear_steep) | ↑慢 | ↑↑快 | 走阔↑ | 经济复苏，基本面推长端 |
| 熊平(bear_flat) | ↑↑快 | ↑慢 | 收窄↓ | 央行收紧，资金面紧张 |

如果收益率变动幅度很小（<3bp），判定为 range_bound（震荡）。

## 何时输出 none
- 期货窄幅震荡（近20日涨跌幅<0.3元）
- 均线粘合无方向
- 成交量持续萎缩至地量

## 输出格式
```json
{
  "signal": "bullish 或 bearish 或 none",

## 4. 曲线形态详细说明

### 四种形态的经济学含义

| 形态 | 短端(1Y) | 长端(10Y) | 10Y-1Y利差 | 触发条件 | 典型阶段 |
|------|----------|-----------|------------|----------|---------|
| 牛陡 | ↓↓快 | ↓慢 | 走阔↑ | 央行降息/降准，资金面先松 | 衰退初期→宽松开启 |
| 牛平 | ↓慢 | ↓↓快 | 收窄↓ | 经济预期持续走弱，配置盘抢长端 | 衰退深化→资产荒 |
| 熊陡 | ↑慢 | ↑↑快 | 走阔↑ | 经济复苏确认，基本面推动长端上行 | 复苏确认期 |
| 熊平 | ↑↑快 | ↑慢 | 收窄↓ | 央行收紧/资金面紧张 | 过热→政策收紧 |

### 形态判定逻辑（calc_curve_shape）

1. 取 1Y 和 10Y 近30日变动幅度(bp)
2. 如果两者变动都小于3bp → range_bound（震荡）
3. 如果都下行 → 牛市；都上行 → 熊市
4. 比较速度：|10Y变动| > |1Y变动| → 平（flat）；反之 → 陡（steep）

### 超长端（30Y）的特殊性

30Y-10Y 利差反映：
- 保险/养老金的超长久期配置需求
- 超长债供给冲击（特别国债等）
- 久期溢价和通胀风险补偿

当 30Y-10Y 利差极度压缩时 → 配置需求拥挤，如果有供给放量容易调整

| 组合 | 价格 | 成交量 | 持仓量 | 含义 | 可信度 |
|------|------|--------|--------|------|--------|

| 减仓放量下跌 | T↓ | ↑ | ↓ | 多头止损 | 中 |

判断方法：
- 价格方向：近5日 vs 前5日均价对比
- 成交量变化：近5日均量 vs 前20日均量
- 持仓量变化：最新持仓 vs 20日前持仓

## 7. LangGraph 并行执行注意事项

5个Agent需要真正并行执行（fan-out），全部完成后汇总到首席（fan-in）。

LangGraph 实现方式：
```python
# 方法1：使用 add_edge 从 START 到多个节点
graph.add_edge(START, "agent_a")
graph.add_edge(START, "agent_b")
# ...

# 方法2：如果版本不支持真正并行，用 Send API
from langgraph.constants import Send

def fan_out(state):
    return [
        Send("agent_a", state),
        Send("agent_b", state),
        Send("agent_c", state),
        Send("agent_d", state),
        Send("agent_e", state),
    ]
```

首席节点需要等待所有5个Agent完成后才执行。检查 LangGraph 版本是否支持此模式。
如果不支持真正并行，可以顺序执行5个Agent（功能相同，只是慢一些），不影响结果。

## 8. 关于 Wind 数据工具的实现细节

### LLM 初始化（每个 Agent 都需要）
```python
from langchain_anthropic import ChatAnthropic
import config

def get_llm(model=None):
    return ChatAnthropic(
        model=model or config.AGENT_MODEL,
        api_key=config.API_KEY,
        base_url=config.BASE_URL,
        max_tokens=4096,
    )

# 专业 Agent 用
agent_llm = get_llm(config.AGENT_MODEL)
# 首席用（可以用更强的模型）
chief_llm = get_llm(config.CHIEF_MODEL)
```

### Wind 连接管理
- w.start() 在程序启动时调用一次
- w.stop() 在程序结束时调用
- 不要在每个函数里重复 start/stop
- 建议用 atexit 注册 w.stop()

### 错误处理
- Wind 未连接时：返回清晰错误提示，建议切换到 AKShare
- 数据返回空值：过滤 None，计算时跳过缺失值
- 代码不存在：返回"该指标不可用"

### 数据格式
- w.edb() 返回 ErrorCode + Data + Times
- w.wsd() 返回 ErrorCode + Data + Times + Fields
- 所有数据转为 pandas DataFrame 处理
